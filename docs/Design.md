# IdeaDock 1.2

Capture first, organize later. A macOS 14+ SwiftUI application with AppKit window ownership, a SwiftData database, and managed image files beside the database. No accounts, network calls, analytics, or clipboard monitoring.

The library has a 190-point native sidebar, a compact idea list, and a roomy text editor. Warm orange identifies selection and capture actions. System fonts, restrained separators, plain surfaces, and native controls provide a calm daily workspace. A smaller library hides the sidebar; the editor can be shown alone.

The default landing view is All Notes, a chronological capture history with automatic day headings. Today and calendar-based time ranges help retrieval without manually creating a folder or tag. Categories are initially collapsed. Captures derive a title, recognize their content type, and record the save time automatically; they never require metadata choices. Original capture times remain stable through editing and pinning, and an unchanged editor does not create a new change timestamp. Compact local date/time appears in rows and floating notes, with full capture date/time in the editor and time-zone detail on hover.

Command-K starts with the latest three captures and searches saved notes alongside commands. Its result order and arrow/Return navigation share the same indices. The desktop capture receipt reopens the note just saved; it is a quiet text row shown only after a successful capture and while the next draft is empty. Search keeps typing focus as results change, includes notes across categories, and combines optional time and content-type filters. Navigation and new captures clear stale filters so a successfully saved note remains discoverable.

An Option-Space Carbon hotkey opens an immediately focused panel. Return saves, Shift-Return inserts a newline, Escape dismisses. A separate desktop surface uses Command-Return to capture multiline drafts and can collapse to a thin bar. Native panels own frame restoration, Spaces behavior, and window level. Each floating idea reuses the editor with a separate frame key.

Desktop capture and individual notes have a dedicated native drag grip. During movement, a translucent orange rail previews the nearest eligible screen edge or corner, using a 22-point threshold and a little hysteresis. Releasing slides and fades the original window into a compact native handle over 0.22 seconds. Clicking the handle restores it; pulling the handle away restores the note under the drag. The existing editor stays alive, preserving its draft, attachments, and selection. Escape suppresses docking until the mouse is released. Right-click grip commands and the Window menu expose the same eight placements without requiring precise mouse movement.

One main-actor edge controller per window owns the preview, handle, drag lifecycle, animation, and a persisted edge record. Geometry calculations accept display visible frames with arbitrary origins. Records preserve display identity, relative rail position, and the note's resting frame; restoring normalizes valid small frames to current minimum dimensions and clamps them to an available display. Frame persistence uses the resting frame while docked or animating, so transient animation coordinates cannot replace a note's saved position. Mini capture keeps a separately normalized expanded size. Handles follow pin, opacity, appearance, and Spaces preferences; macOS Reduce Motion removes spatial animation.

One main-actor store owns SwiftData mutations. Attachment records distinguish owned images from referenced files. Files use bookmarks and a fallback path; images are copied to Application Support/IdeaDock/Attachments. Explicit saves report errors. Export JSON embeds image bytes for portable restore; Markdown export includes an attachments directory. Import merges IDs and validates data before mutation.

Build after each phase. Verify persistence, organization, content detection, attachments, export/import, and cleanup through an isolated executable test mode. Inspect and exercise the real native app using accessibility and screenshots. Optional WidgetKit is deferred when full Xcode/signing support is unavailable.
